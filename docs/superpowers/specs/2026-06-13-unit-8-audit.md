### Headline observations from the visual pass

These bubbled up across multiple surfaces during the actual side-by-side review:

1. **Theme inconsistency.** `/auth/login`, `/auth/recovery`, `/onboarding` all render on
   LIGHT background (matching system preference?) while authenticated surfaces and `/pair`
   default to DARK. The design treats the auth flow as a cosmic dark surface; either
   force-dark for auth (matches design intent) or honor system pref. Decide before 8a.
2. **Form input bg leaks across themes.** Modal-change-password and modal-view-recovery-code
   show inputs with LIGHT bg even though the page underneath is DARK. The input primitive
   isn't theme-aware. Likely a `<Input>` component bug from Unit 7's theming work — worth
   triaging during 8c (modal shell) or as a separate prep task.
3. **Sidebar header avatar missing.** `conv-list-empty` sidebar header shows just text
   "Alice Audit" with no avatar to the left. Unit 4's polymorphic profile design implied
   the avatar would be the tap target into `/profile/<me>`. Either re-add the avatar or
   make the whole header row tappable (audit hook `[data-testid="sidebar-header-profile"]`
   exists per Unit 4, but no visible avatar rendered).
4. **Two contacts routes.** The standalone `/contacts` route survives alongside the sidebar
   `contacts` tab. They're not visually identical (the standalone has a "← Conversations"
   back-link + "Contacts" page title, the tab has neither). Decide: deprecate the standalone
   route, or unify the visual treatment, or keep distinct as deep-link entry. 8d candidate.
5. **Section titles inconsistent.** Settings page has sentence-case section labels
   ("Profile", "Appearance", "Give feedback", "Notifications") while the design uses
   lowercase. Same pattern across most surfaces. Bulk typography pass during 8e or a
   dedicated typography fix commit.
6. **Onboarding welcome step has long subtitle.** Live: "A local-first, end-to-end encrypted
   messenger. Your account is protected by a password you control; a 24-word recovery code
   is your escape hatch if you forget it." Design's welcome scene uses just "local-first ·
   end-to-end encrypted" — the Wordmark carries the brand, the subtitle is single-line.
7. **Onboarding CTA labels diverge from design.** Live: "Create new account" + "Sign in to
   existing account". Design: "create account" + "restore from recovery code" + (separate
   row) "already on a device? sign in". The split treatment surfaces the recovery affordance
   first; the live UI subordinates it.
8. **Modal Card wrapper missing entirely.** Both modals captured show floating inputs over
   the scrim, no Card. Looks unfinished. Confirms 8c as the highest-leverage modal fix.
9. **`/contacts/add` is in BETTER shape than assumed.** Lowercase title + subtitle, "YOUR
   CODE" uppercase tracking-widest header, panel-bordered QR card, "copy link"/"share" outline
   buttons (lowercase), TTL pill picker with accent fill, "ADD SOMEONE" divider, "scan their
   code" primary CTA (lowercase). Mostly nit-level. The main need is toast-wiring on copy
   (sub-unit 8e).
10. **Pair-responder has a Card wrapper but no AuthSurface.** Better than auth-login's bare
    layout, but design wraps everything in cosmic AuthSurface; the Card-over-bg-void is
    halfway there. Promoting to AuthSurface means dropping the Card border and overlaying the
    Lattice watermark + dot sprinkles.

| `--nox-grad-primary` (blue→violet) | missing | present | **adopt** — needed for hi-fi flourish surfaces (welcome wordmark gradient, rule dividers) |
| `--nox-grad-rule` (blue→violet→transparent) | missing | present | **adopt** — used by section dividers in design |
| `--nox-grad-cosmic` (cosmic radial) | missing | present | **adopt** — used by AuthSurface backdrop in design (or replicated by Lattice + dot sprinkles per current Lattice component) |

**Action summary.** Three new gradient tokens to introduce (`--nox-grad-primary`,
`--nox-grad-rule`, `--nox-grad-cosmic`). Optionally normalise the light palette to be
explicit. The named accent triad (`--nox-blue/violet/cyan`) is worth introducing **only** if
the design's multi-color star sprinkles are kept; otherwise the existing `--color-accent` flip
handles single-accent surfaces fine.

Token deltas are a **prep task** that lands before any Phase B sub-unit dispatches.
